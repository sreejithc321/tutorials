LangChain, LangGraph & LangSmith

A beginner's guide to building, orchestrating, and monitoring LLM applications

The Three Frameworks

LangChain: Build LLM applications with components like chains and agents • LangGraph: Create complex workflows with branching, loops, and state management • LangSmith: Monitor, debug, and evaluate your applications in production

🔗 LangChain: Building Blocks

What it is: A framework that makes it easy to build LLM applications by providing pre-built components you can combine.

Simple analogy: Like LEGO blocks. Instead of building from scratch, you snap together pre-made pieces.

Components You Get

Models: Connect to Claude, GPT, and other LLMs

Prompts

Prompt Templates: Reusable, dynamic prompts with variables

Chains

Chain Multiple Steps: Connect prompts, models, tools in sequence

Agents

Autonomous Behavior: LLM decides which tools to use and when

Memory

Conversation History: Remember previous messages and context

Document Loaders

Load Any Format: PDFs, CSVs, web pages, databases

📊 LangGraph: Complex Workflows

What it is: Builds on LangChain to handle complex workflows with branching logic, loops, and state management.

Simple analogy: If LangChain is a straight line, LangGraph is a flowchart with decisions and loops.

Start
→
Decision
→
Action A
→
End

LangGraph lets you build workflows like this with:

  • Nodes - Steps that do work
  • Edges - Connections between steps
  • Conditional logic - Route based on conditions
  • State - Track data through the workflow
  • Loops - Go back to earlier steps
👁️ LangSmith: Monitoring & Debugging

What it is: A platform to see, debug, and improve your LLM applications in production.

Simple analogy: Like a dashboard for your car showing engine health, fuel, temperature, etc.

What you get:

  • 📝 Trace - See every step your app takes
  • 🐛 Debug - Find where things go wrong
  • 📊 Metrics - Track latency, cost, errors
  • 📈 Analytics - Understand usage patterns
  • ⭐ Evaluate - Score output quality
  • 🔁 Iterate - Test improvements before deploying

📈 From Simple to Complex
1 Simple: Just LangChain

Good for: Simple chains, basic agents, RAG systems

Pros:

  • Simple, fast to build
  • Good for prototypes

Cons:

  • Hard to handle complex logic
  • No state management
  • Difficult branching
2 Medium: LangChain + LangGraph

Good for: Workflows with decisions, loops, complex agents

Pros:

  • Handle complex logic
  • Branching and loops
  • State management

Cons:

  • Need to understand graph patterns
3 Advanced: All Three + LangSmith

Good for: Production systems, complex agents, monitoring, optimization

Pros:

  • Full visibility into system
  • Debug issues easily
  • Optimize based on data
  • Production-ready

Cons:

  • More complex setup
  • Learning curve
🎯 When to Use Each

Use just LangChain if:

  • Building a quick prototype
  • Simple RAG system
  • Linear chains without branching

Add LangGraph if:

  • Need conditional logic (if/else)
  • Loops and retries
  • Complex multi-agent systems
  • Need to track state

Add LangSmith if:

  • Going to production
  • Need to debug issues
  • Want to monitor quality
  • Need to optimize costs
  • Comparing prompts/models
🚀 Simple Project: Customer Support Agent

We'll build a customer support agent that handles tickets, escalates when needed, and tracks everything with LangSmith.

Project Goal

Build a system using LangChain (chains), LangGraph (workflow with escalation logic), and monitor with LangSmith (see what's happening)

📋 Step-by-Step Implementation
1 Install Libraries

Get the tools you need:

    langgraph langsmith python-dotenv
2 Set Up LangSmith

Create free account and get API key from langsmith.com, then:

3 Build with LangChain + LangGraph

Create support_agent.py:

from langchain_anthropic import ChatAnthropic
from langchain.prompts import PromptTemplate
from langchain.chains import LLMChain
from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated
import operator
import json
import os

# ==================== SETUP ====================
os.environ["LANGSMITH_TRACING"] = "true"

llm = ChatAnthropic(model="claude-opus-4-1")

# ==================== LANGCHAIN COMPONENTS ====================
class SupportChain:
    """LangChain components for support"""
    
    def __init__(self):
        # Triage prompt - decide if this is simple or complex
        triage_prompt = PromptTemplate(
            input_variables=["customer_issue"],
            template="""You are a support triage agent. 
            Analyze this customer issue and decide: simple or complex?
            
            Issue: {customer_issue}
            
            Output only: SIMPLE or COMPLEX"""
        )
        
        # Response generation
        response_prompt = PromptTemplate(
            input_variables=["customer_issue"],
            template="""You are a helpful support agent.
            Respond to this customer issue professionally:
            
            Issue: {customer_issue}
            
            Provide a helpful response."""
        )
        
        self.triage_chain = LLMChain(
            llm=llm,
            prompt=triage_prompt
        )
        
        self.response_chain = LLMChain(
            llm=llm,
            prompt=response_prompt
        )
    
    def triage(self, issue):
        """Determine complexity"""
        result = self.triage_chain.run(customer_issue=issue)
        return "COMPLEX" in result.upper()
    
    def respond(self, issue):
        """Generate response"""
        result = self.response_chain.run(customer_issue=issue)
        return result

# ==================== LANGGRAPH STATE & NODES ====================
class TicketState(TypedDict):
    """State for the support workflow"""
    customer_issue: str
    is_complex: bool
    response: str
    escalated: bool
    agent_notes: str

def receive_ticket(state: TicketState) -> TicketState:
    """Node 1: Receive and log ticket"""
    print(f"\\n📬 Received ticket: {state['customer_issue'][:50]}...")
    state["agent_notes"] = "Ticket received"
    return state

def analyze_ticket(state: TicketState) -> TicketState:
    """Node 2: Analyze complexity"""
    support = SupportChain()
    is_complex = support.triage(state["customer_issue"])
    state["is_complex"] = is_complex
    state["agent_notes"] += f" → Analyzed (complex={is_complex})"
    print(f"🔍 Complexity: {'HIGH' if is_complex else 'LOW'}")
    return state

def handle_simple(state: TicketState) -> TicketState:
    """Node 3a: Handle simple tickets"""
    support = SupportChain()
    response = support.respond(state["customer_issue"])
    state["response"] = response
    state["escalated"] = False
    state["agent_notes"] += " → Handled (SIMPLE)"
    print(f"✅ Simple response generated")
    return state

def escalate_ticket(state: TicketState) -> TicketState:
    """Node 3b: Escalate complex tickets"""
    state["response"] = "This issue needs human expertise. Escalating..."
    state["escalated"] = True
    state["agent_notes"] += " → ESCALATED to human"
    print(f"⚠️ Escalated to human agent")
    return state

def create_summary(state: TicketState) -> TicketState:
    """Node 4: Create summary"""
    summary = {
        "issue": state["customer_issue"][:100],
        "complexity": "HIGH" if state["is_complex"] else "LOW",
        "escalated": state["escalated"],
        "response": state["response"][:100] if state["response"] else "N/A",
        "notes": state["agent_notes"]
    }
    print(f"\\n📋 Summary: {json.dumps(summary, indent=2)}")
    return state

# ==================== BUILD LANGGRAPH WORKFLOW ====================
def should_escalate(state: TicketState) -> str:
    """Conditional logic: route based on complexity"""
    return "escalate" if state["is_complex"] else "simple"

def build_graph():
    """Create the workflow graph"""
    graph = StateGraph(TicketState)
    
    # Add nodes
    graph.add_node("receive", receive_ticket)
    graph.add_node("analyze", analyze_ticket)
    graph.add_node("simple", handle_simple)
    graph.add_node("escalate", escalate_ticket)
    graph.add_node("summary", create_summary)
    
    # Add edges
    graph.add_edge(START, "receive")
    graph.add_edge("receive", "analyze")
    
    # Conditional edge - branch based on complexity
    graph.add_conditional_edges(
        "analyze",
        should_escalate,
        {
            "simple": "simple",
            "escalate": "escalate"
        }
    )
    
    # Both paths lead to summary
    graph.add_edge("simple", "summary")
    graph.add_edge("escalate", "summary")
    graph.add_edge("summary", END)
    
    return graph.compile()

# ==================== MAIN ====================
if __name__ == "__main__":
    print("🤖 Customer Support Agent with LangChain + LangGraph + LangSmith\\n")
    
    # Build workflow
    workflow = build_graph()
    
    # Test cases
    test_tickets = [
        "My password isn't working, how do I reset it?",
        "I found a complex security vulnerability in your system that could expose customer data. Details at [...]"
    ]
    
    for ticket in test_tickets:
        print(f"\\n{'='*60}")
        
        # Run through workflow
        result = workflow.invoke({
            "customer_issue": ticket,
            "is_complex": False,
            "response": "",
            "escalated": False,
            "agent_notes": ""
        })
        
        print(f"\\n✅ Ticket processed")
        print(f"   Escalated: {result['escalated']}")
    
    print(f"\\n{'='*60}")
    print("✨ Check LangSmith dashboard for full traces!")
    print("   Visit: https://smith.langchain.com/")

🔗 Deep Dive: LangChain Details
Key Components ›

1. LLM Model

Connect to any LLM (Claude, GPT, Llama, etc.)

2. Prompt Templates

Dynamic prompts with variables. Reuse across projects.

3. Chains

Combine prompts → model → output in sequence

4. Tools & Agents

Define what agent can do (APIs, searches, calculations)

5. Memory

Store conversation history. Types: buffer, summary, entity

6. Document Loaders

Load PDFs, CSVs, web pages, docs for RAG

Common Patterns ›

Sequential Chain

A → B → C (output of A is input for B)

Router Chain

Decide which chain to use based on input

Memory Chain

Remember conversation history

Agent Loop

LLM decides which tools to use, loops until done

📊 Deep Dive: LangGraph Details
Graph Concepts ›

Nodes: Functions that do work. Similar to steps in a flowchart.

Edges: Connections between nodes. Define the flow.

Conditional Edges: Route to different nodes based on state. Like if/else statements.

State: Data passed between nodes. Shared context.

graph = StateGraph(MyState) graph.add_node("step1", func1) graph.add_node("step2", func2) graph.add_node("step3", func3) graph.add_edge("step1", "step2") graph.add_conditional_edges( "step2", should_continue, # function that decides { "yes": "step3", "no": END } )
When to Use Graph Patterns ›

Linear Flow

A → B → C. No branching. Use simple chains.

Conditional Flow

If X, do A; else do B. Use conditional edges.

Loops

Retry or repeat until condition met. Connect edge back to earlier node.

Parallel Paths

Multiple tasks at same time. Use parallel node execution.

👁️ Deep Dive: LangSmith Details
What LangSmith Tracks ›

Traces: Complete record of one execution. See every step, every call.

Spans: Individual operations within a trace. Nested hierarchy.

Runs: Individual invocations of your system. Track over time.

Feedback: Rate quality of outputs. 👍/👎 or custom scores.

Metrics: Latency, cost, error rate, quality. Aggregated over time.

Using LangSmith for Debugging ›

1. View Traces

See exactly what happened step by step

2. Check Inputs/Outputs

See exact prompts sent and responses received

3. Find Errors

Spot where things went wrong

4. Compare Versions

Test new prompts/models before deploying

5. Analyze Patterns

Find common failure modes across runs

Adding Feedback & Evals ›

Manual Feedback: Thumbs up/down on outputs

Automatic Evals: Score quality with another LLM

Scoring Functions: Custom metrics for your use case

Example: For customer support, score if agent escalated correctly

🏗️ Architecture Patterns
Simple RAG with LangChain ›
1. Load documents (PDFs, docs) 2. Split into chunks 3. Create embeddings 4. Store in vector DB 5. On query: - Retrieve relevant chunks - Build prompt with chunks - Send to LLM - Return answer with sources

Perfect for knowledge bases, FAQs, documentation Q&A

Agent with Tools (LangChain + LangGraph) ›
LLM sees available tools LLM decides which to use Execute tool Pass result back to LLM LLM decides next action Repeat until done Graph handles the loop: - Node: "think" → LLM decides - Node: "act" → execute tool - Conditional: "continue?" → yes/no

Good for search, calculation, API calls

Multi-Agent Coordinator (All Three) ›
Coordinator Agent (LangChain) ├── Can use router chains └── Routes to specialist agents Specialist Agents (LangGraph) ├── Research Agent ├── Writer Agent └── Editor Agent LangSmith monitors: - What each agent did - How long it took - Where errors occurred - Quality of outputs

Good for complex projects requiring specialization

⚠️ Common Pitfalls & Solutions
Infinite Loops ›

Problem: Agent keeps doing same thing forever

Solution: Set max iterations. Track what's been tried. Add clear exit conditions.

Cost Explosion ›

Problem: Agent makes many LLM calls, costs add up

Solution: Use cheaper models for simple steps. Cache prompts. Limit iterations. Monitor in LangSmith.

State Management Issues ›

Problem: Data gets lost between nodes or modified unexpectedly

Solution: Use TypedDict to define state clearly. Always return updated state from nodes. Use immutable patterns.

Debugging Complex Graphs ›

Problem: Multi-agent system is hard to understand

Solution: Use LangSmith to visualize. Test each node independently first. Add debug logging. Visualize graph structure.
