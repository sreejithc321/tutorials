Understanding RAG in Python

A beginner's guide to Retrieval-Augmented Generation

What is RAG?

RAG stands for "Retrieval-Augmented Generation." It's a technique that lets AI models (like Claude) access and learn from your documents, databases, or knowledge bases in real-time. Instead of relying only on what the AI already knows, RAG retrieves relevant information first, then uses it to give better answers.

🧠 How AI Works Without RAG

Regular AI: The model has knowledge from its training data, which is frozen in time. It can't access new information or your personal documents.

Example: Ask Claude about a document you just created, and it won't know anything about it because it wasn't in the training data.

✨ How AI Works With RAG

RAG-Enhanced AI: The model first searches your documents, finds relevant information, then uses that information to answer your question.

Example: Ask Claude about your document, RAG finds the relevant parts, and Claude answers accurately based on your actual content.

🔄 RAG in Three Steps
1 Retrieve
Search your documents to find relevant information that matches the user's question.
2 Augment
Add the retrieved information to the AI's context (like giving it additional reference material).
3 Generate
The AI reads the context and generates an accurate answer based on your actual documents.

❌ Problems RAG Solves

Problem 1: Hallucinations

AI models sometimes make up facts that sound true but are wrong. RAG prevents this by giving the AI real information to work with.

Problem 2: Outdated Knowledge

AI training happens at a specific point in time. Information after that date is unknown. RAG lets AI access current documents and information.

Problem 3: Private Information

You can't ask an AI about private company documents or confidential files. RAG lets you safely give the AI access to specific documents.

Problem 4: Context Length Limits

AI models can only "remember" a limited amount of text. RAG finds the most relevant information, so you don't hit those limits.

3 Build Simple RAG System

Create simple_rag.py:

import os
import glob
from anthropic import Anthropic

# 1. LOAD DOCUMENTS
documents = []
for file_path in glob.glob("documents/*.txt"):
    with open(file_path, 'r') as f:
        documents.append({
            "name": os.path.basename(file_path),
            "content": f.read()
        })

print(f"Loaded {len(documents)} documents")

# 2. SIMPLE SEARCH (find relevant docs)
def search_documents(query, documents):
    """Find documents that mention keywords from the query"""
    query_words = query.lower().split()
    relevant_docs = []
    
    for doc in documents:
        content_lower = doc['content'].lower()
        # Count how many query words appear in this doc
        matches = sum(1 for word in query_words 
                     if word in content_lower)
        
        if matches > 0:
            relevant_docs.append({
                "name": doc['name'],
                "content": doc['content'],
                "relevance": matches
            })
    
    # Sort by relevance (most relevant first)
    relevant_docs.sort(key=lambda x: x['relevance'], reverse=True)
    return relevant_docs

# 3. SETUP AI CLIENT
client = Anthropic()

# 4. MAIN CONVERSATION LOOP
print("\n📚 RAG Q&A System Started!")
print("Ask questions about your documents (type 'quit' to exit)\n")

while True:
    question = input("Your question: ").strip()
    
    if question.lower() == 'quit':
        break
    
    # Step 1: RETRIEVE - Find relevant documents
    relevant_docs = search_documents(question, documents)
    
    if not relevant_docs:
        print("No relevant documents found.\n")
        continue
    
    # Step 2: AUGMENT - Create context from retrieved documents
    context = "Here are relevant documents:\n\n"
    for doc in relevant_docs[:3]:  # Use top 3 most relevant
        context += f"From {doc['name']}:\n"
        context += doc['content']
        context += "\n\n---\n\n"
    
    # Step 3: GENERATE - Ask AI to answer using the context
    system_prompt = """You are a helpful assistant that answers 
    questions based on the provided documents. 
    Only use information from the documents. 
    If the answer isn't in the documents, say so."""
    
    response = client.messages.create(
        model="claude-opus-4-1",
        max_tokens=1024,
        system=system_prompt,
        messages=[
            {
                "role": "user",
                "content": f"{context}\n\nQuestion: {question}"
            }
        ]
    )
    
    print(f"\nAnswer: {response.content[0].text}\n")
    print("-" * 50 + "\n")

🔍 Understanding RAG Architecture

Why RAG is Powerful

RAG combines the strengths of search systems (finding relevant info fast) with AI (understanding and writing naturally). This creates a system that's both accurate and intelligent.

🧩 Core Components Explained
Embeddings ›

What it is: A way to convert text into numbers that computers can compare.

Simple analogy: Imagine assigning a "fingerprint" to every sentence. Similar sentences get similar fingerprints. Then you can quickly find sentences with the same fingerprint.

Example:

"How many vacation days?" 
→ [0.12, -0.45, 0.89, 0.23, ...]

"Vacation policy days" 
→ [0.13, -0.44, 0.88, 0.24, ...]

These two are similar (small differences) so the system knows they're related!

Vector Databases ›

What it is: A database designed to store and quickly search through embeddings (those number fingerprints).

Why special?: Regular databases search by exact matches. Vector databases find similar items, which is perfect for finding relevant documents.

Popular options:

  • Pinecone - Cloud-based, easy to use
  • Weaviate - Open-source, flexible
  • Chroma - Simple, great for learning
  • FAISS - Facebook's library, very fast
  • Milvus - Open-source, enterprise-ready
Chunking ›

What it is: Breaking large documents into smaller pieces (chunks) before storing them.

Why needed?: A 100-page document has too much information in one chunk. You want to retrieve only the relevant section, not the whole document.

Example:

Original: 50-page employee handbook

After chunking:
Chunk 1: Work Hours Policy (200 words)
Chunk 2: Vacation Policy (300 words)
Chunk 3: Remote Work Rules (250 words)
... and so on

When you ask about vacation,
only Chunk 2 is retrieved!
Retrieval Methods ›

Simple Retrieval (Keyword Search)

Find documents based on keywords. Fast but sometimes misses relevant content.

Semantic Retrieval (Embedding Search)

Convert question and documents to embeddings, find most similar. Slower but understands meaning.

Hybrid Retrieval

Combine both methods. Best results!

Reranking ›

What it is: A second pass to re-score retrieved documents and pick the best ones.

Why?: Your initial retrieval might bring back 100 results. A reranker scores them and returns only the top 5 most relevant.

Process:

1. Initial Retrieval: Returns 100 documents
2. Reranker: Scores all 100 documents
3. Final Selection: Return top 5 best matches
4. AI Generation: Claude answers using those 5
🔄 Complete RAG Pipeline
1️⃣ Document Preprocessing Load documents → Clean text → Break into chunks → Create embeddings
2️⃣ Indexing Store chunk embeddings in vector database with metadata
3️⃣ Query Processing Convert user question into embedding
4️⃣ Retrieval Search vector database for similar chunks
5️⃣ Ranking (Optional) Rerank results to get the best matches
6️⃣ Context Building Combine retrieved chunks with the original question
7️⃣ Generation Send context + question to LLM, get answer
8️⃣ Response Return answer to user with source references
⚡ Advanced Techniques
Query Expansion ›

What it does: Takes your question and rewrites it several ways to find more relevant documents.

Example:

Original: "vacation days"

Expanded versions:
- "How many vacation days do employees get?"
- "Time off policy"
- "Annual leave allowance"
- "Days off per year"

Each version might retrieve different relevant chunks!

Multi-Step Retrieval ›

What it does: The AI can make multiple searches, each based on what it learned from the previous search.

Example:

Question: "What happens if I take unpaid leave?"

Step 1 - Retrieve: "unpaid leave policy"
Step 2 - Read result: Find it mentions health insurance
Step 3 - Retrieve again: "health insurance during leave"
Step 4 - Answer: Using both searches

More comprehensive answer!
Metadata Filtering ›

What it does: Add extra information (metadata) to documents like date, author, or category, then filter by this metadata.

Example:

Document metadata:
{
  "content": "vacation policy...",
  "source": "employee_handbook.pdf",
  "date": "2024-01-01",
  "category": "HR_Policy",
  "version": "2.0"
}

Filter: Only search HR_Policy documents from 2024

❓ Common Questions
Is RAG better than fine-tuning? ›

Different tools for different jobs:

RAG: Best when you need to use current documents and don't want to retrain. Faster to set up.

Fine-tuning: Best when you want the model to deeply learn your domain. Takes longer, costs more.

Many projects use both together!

How much data do I need? ›

RAG works with any amount of data:

  • Small: 5-10 documents → Works great
  • Medium: 100s of documents → Works well
  • Large: Millions of documents → Still works, might need optimization

Start small, scale up gradually!

What about hallucinations in RAG? ›

RAG dramatically reduces hallucinations, but doesn't eliminate them:

Regular AI: 20-30% hallucination rate

RAG AI: 2-5% hallucination rate

How to reduce further:

  • Ask AI to cite sources
  • Use reranking
  • Add instructions to only use provided context
  • Use retrieval confidence scores
How do I measure RAG quality? ›

Key metrics:

  • Retrieval Precision: Are retrieved documents actually relevant? (Aim: 80%+)
  • Retrieval Recall: Did we find all relevant documents? (Aim: 80%+)
  • Answer Accuracy: Are final answers correct? (Aim: 90%+)
  • Source Attribution: Can answers cite where they came from?
  • Latency: How fast does it respond? (Aim: < 2 seconds)
