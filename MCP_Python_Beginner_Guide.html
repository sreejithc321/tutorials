Understanding MCP in Python

A beginner's guide to the Model Context Protocol

What is MCP?

MCP stands for "Model Context Protocol." It's like a rulebook that lets AI models (like Claude) understand and work with your tools, files, and data. Think of it as a translator between AI and your computer applications.

Basics
Simple Project
Deep Dive
📚 The Simple Explanation

Without MCP: An AI model can only see text. It can't access your calendar, files, or run your programs.

With MCP: You give the AI a set of instructions (like a toolbox). Now it can open files, run programs, ask for information, and much more.

🎯 Why Do We Need It?
1 Connect AI to Real Tools
AI can now use your calendar, email, code editor, or any app that supports MCP.
2 Safe & Controlled Access
You decide exactly what the AI can and cannot do. It's like giving permission to specific actions.
3 Reusable for Everyone
Once someone creates an MCP for a tool, anyone can use it. No need to reinvent the wheel.
⚙️ Key Concepts (Simple Version)
Server

The program that offers tools (like a restaurant menu)

Client

The program that uses those tools (like a customer ordering)

🚀 Our Simple Project: A Weather Tool

We'll create an MCP server that lets AI check the current weather and get weather forecasts.

Project Goal

Build a Python program that: (1) Provides weather data, (2) Lets an AI client ask for weather, (3) Returns weather information back to the AI

📋 Step-by-Step Walkthrough
1 Set Up Your Computer

First, make sure you have Python installed and the MCP library.

pip install mcp

This installs the tools you need to build an MCP server.

2 Create a Simple MCP Server

Create a file called weather_server.py:

from mcp.server import Server
from mcp.types import Tool, TextContent

# Create an MCP server
server = Server("weather-server")

# Define a tool for getting weather
@server.list_tools()
async def list_tools():
    return [
        Tool(
            name="get_weather",
            description="Get the current weather for a city",
            inputSchema={
                "type": "object",
                "properties": {
                    "city": {
                        "type": "string",
                        "description": "City name"
                    }
                }
            }
        )
    ]

# When someone asks for weather, this runs
@server.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "get_weather":
        city = arguments.get("city")
        # Dummy weather data (in real life, call a weather API)
        weather_data = {
            "London": "Rainy, 12°C",
            "Paris": "Sunny, 18°C",
            "Tokyo": "Cloudy, 22°C"
        }
        result = weather_data.get(city, "City not found")
        return [TextContent(type="text", text=result)]
3 Run Your Server

In your terminal, run:

python weather_server.py

Your MCP server is now running! It's waiting for clients to ask for weather.

4 Connect a Client (The AI)

Now create a weather_client.py file that connects to your server:

import asyncio
from mcp.client import ClientSession
from mcp.stdio_client import StdioClientTransport

async def main():
    # Connect to the MCP server
    transport = StdioClientTransport(
        command="python",
        args=["weather_server.py"]
    )
    
    async with ClientSession(transport) as session:
        # Ask the server what tools it has
        tools = await session.list_tools()
        print("Available tools:", [t.name for t in tools])
        
        # Use a tool - ask for London's weather
        result = await session.call_tool(
            "get_weather",
            {"city": "London"}
        )
        print("Weather:", result)

asyncio.run(main())
5 See It In Action

Run your client:

python weather_client.py

Output:

Available tools: ['get_weather'] Weather: Rainy, 12°C
💡 What Just Happened?
  1. Your server told the client "I can get weather"
  2. Your client asked "Hey server, what's the weather in London?"
  3. Your server looked it up and replied "Rainy, 12°C"
  4. The client received the answer
🔍 Understanding the Architecture

Client-Server Model

MCP uses a client-server architecture. Your server offers tools, and clients use them. This is the same pattern used across the internet!

🛠️ Components Explained
Server ›

What it is: A Python program that exposes tools and resources.

Example: Your weather server is an MCP server. It defines the "get_weather" tool.

Responsibilities:

  • List available tools
  • Handle tool calls
  • Return results
  • Manage permissions
Client ›

What it is: A program that connects to an MCP server and uses its tools.

Example: Claude (the AI) can be a client. It connects to your weather server and asks for weather.

Responsibilities:

  • Connect to servers
  • Discover available tools
  • Call tools when needed
  • Process results
Tools ›

What it is: Functions or actions that the server can perform.

Example: "get_weather" is a tool. It takes a city name and returns weather.

Parts of a tool definition:

Tool(
    name="get_weather",           # Tool ID
    description="Get weather",    # What it does
    inputSchema={...}             # What it needs as input
)
Resources ›

What it is: Data or files that the server can share.

Example: A list of cities and their time zones, or a file with historical weather data.

Unlike tools: Resources are static data, not actions. Tools do things; resources provide information.

📊 Request & Response Flow

What happens when a client calls a tool:

1. Client → Server: "I want to call get_weather with city='London'" 2. Server receives request 3. Server runs get_weather("London") 4. Server gets result: "Rainy, 12°C" 5. Server → Client: "Here's your result: Rainy, 12°C" 6. Client receives and uses the result
🔐 Security & Permissions

Why it matters: You don't want the AI doing dangerous things like deleting files or accessing sensitive data.

Control What's Exposed

Only list tools that are safe for the AI to use. Don't expose file deletion tools unless absolutely necessary.

Validate Input

Always check that the AI is sending valid data. Don't blindly trust what it sends.

Use Schemas

Define exactly what input format your tools expect. This prevents misuse.

💬 Common Questions
Is MCP the same as API? ›

Simple answer: Similar, but not the same.

API = Any system for programs to talk to each other.

MCP = A specific protocol designed for AI models to understand and use tools safely.

Can I use MCP for anything besides AI? ›

Technically yes, but it's designed for AI. You'd be better off using regular APIs for non-AI applications. MCP's special features help AI models understand what tools do.

How hard is it to create an MCP server? ›

Not hard at all! You saw a simple weather server in just 20 lines of code. As you build more, you can add:

  • Multiple tools
  • Complex logic
  • Database connections
  • Error handling
Can multiple clients use the same server? ›

Yes! Once your server is running, any number of clients can connect and use it. This is one of the biggest advantages—write once, use everywhere.
