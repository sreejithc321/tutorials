Cost Optimization for LLMs

Strategies to reduce your LLM bill by 50-90% without sacrificing quality

The Goal

Most teams waste 40-60% on LLM costs by not optimizing. This guide shows you proven techniques to cut costs significantly while maintaining or improving quality.

💰 Understanding LLM Costs

How you pay for LLMs: By tokens (not per request, not per hour)

Token basics: 1 token ≈ 4 characters. Usually charged per 1,000 tokens.

Typical pricing (per 1M tokens):

Model Input Cost Output Cost Best For
Claude 3.5 Haiku $0.80 $4.00 Fast, cheap
Claude 3.5 Sonnet $3.00 $15.00 Best balance
Claude 3 Opus $15.00 $75.00 Most capable
GPT-4o Mini $0.15 $0.60 Ultra cheap
Llama 3 (AWS) $0.30 $0.60 Open source

Total cost formula:

Total Cost = (Input Tokens × Input Rate) + (Output Tokens × Output Rate)

📊 Cost Example: The Problem

Typical wasteful scenario:

Using Claude 3 Opus for everything. 1M requests/month. Average 500 input tokens, 200 output tokens.

Cost: $500M × ($15 + $75) × (1M/1M) ≈ $45,000/month

With Cost Optimization

Use right model for each task + caching + batching + context reduction

Cost: 90% reduction ≈ $4,500/month

🎯 Four Pillars of Cost Optimization
1 Right Model Selection
Use cheapest model that works for the task. Haiku for simple, Sonnet for complex, Opus only when needed.
2 Token Reduction
Fewer tokens = lower cost. Optimize prompts, compress context, use summarization.
3 Caching & Batching
Reuse results (caching). Process many at once (batching). Avoid duplicate work.
4 Monitoring & Control
Track costs continuously. Set budgets and alerts. Identify wasteful patterns.
⚡ Quick Wins (Start Here)

Quick Win #1: Right Model for Task

Haiku is 5x cheaper than Sonnet, 75x cheaper than Opus. For tasks like summarization, classification, extraction → Use Haiku first.

Quick Win #2: Prompt Caching

If you use same document/system prompt repeatedly → Cache it. Save 90% on that cost. Takes 2 minutes to implement.

Quick Win #3: Token Counting Before Sending

Count tokens before API call. Skip requests that exceed budget. Prevents runaway costs. Free to implement.

Quick Win #4: Batch Processing

Instead of 1,000 individual API calls → 10 batch calls. Same results, 90% cheaper. Takes a few hours to refactor.

🛠️ Strategy 1: Model Selection
Choosing the Right Model ›

Haiku (Cheapest):

  • Text summarization
  • Classification (sentiment, category)
  • Simple extraction
  • Question answering (simple)
  • Paraphrasing

Sonnet (Best Balance):

  • General purpose (most things)
  • Content creation
  • Code analysis
  • Complex extraction
  • Reasoning tasks

Opus (Only When Needed):

  • Very complex reasoning
  • Advanced math/science
  • Nuanced understanding
  • Creative writing
  • Legal/financial analysis
Model Selection Decision Tree ›

Start here: Use Haiku

Test if it works. If quality is good enough → Done. Save money.

If Haiku doesn't work: Try Sonnet

9 out of 10 times Sonnet will work. Rarely need Opus.

Only use Opus if:

  • Sonnet consistently fails
  • Task is worth the extra cost
  • You're okay paying 5-10x more
📉 Strategy 2: Token Reduction
Optimizing Prompts ›

Bad prompt (200 tokens):

Please analyze the following document and provide me with 
a comprehensive summary of the key points, main arguments, 
supporting evidence, conclusions and any recommendations that 
are mentioned in this document. I would really appreciate it if 
you could make sure to include all the important details.

Good prompt (50 tokens):

Summarize: key points, arguments, evidence, conclusion

Optimization tips:

  • Remove fluffy language
  • Use bullet points not paragraphs
  • Be direct and concise
  • Structured output (JSON) not text
  • Examples should be minimal
Context Compression ›

Problem: You have 100KB document, user asks 1 question. Full context = 25,000 tokens.

Solution 1: Extract relevant parts

Use search/embeddings to find relevant sections. Pass only those (2,000 tokens).

Solution 2: Summarize first

Summarize large document (use cheap model). Use summary instead of full doc.

Solution 3: Hierarchical processing

Chunk → Summary of each chunk → Summary of summaries

Token Counting Strategies ›

Before sending request: Count tokens

from anthropic import Anthropic

client = Anthropic()

# Count tokens without making request
response = client.messages.count_tokens(
    model="claude-3-5-haiku-20241022",
    messages=[
        {"role": "user", "content": "Your prompt here"}
    ]
)

print(f"Input tokens: {response.input_tokens}")

# Decision: Should we proceed?
if response.input_tokens > 100000:
    print("Too many tokens, skip or compress")
else:
    print("Safe to proceed")

Use for: Budget control, preventing runaway costs, optimizing batch sizes

⚡ Strategy 3: Prompt Caching
How Prompt Caching Works ›

Problem: Same system prompt + document sent 1000x/day

Solution: Cache the system prompt + document

First time (full cost) → Cached for 5 minutes

Next 999 times (90% discount)

Cost example:

  • Without caching: 1000 requests × 10,000 tokens = $30
  • With caching: 1 full + 999 cached = $0.30 + $3 = $3.30
  • Savings: 89%
Implementing Prompt Caching ›

What can be cached:

  • System prompts
  • Long documents
  • Instructions + examples
  • Knowledge base context

Implementation:

response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": "You are a helpful assistant."
        },
        {
            "type": "text",
            "text": "[Large document here - 10,000 tokens]",
            "cache_control": {"type": "ephemeral"}
        }
    ],
    messages=[
        {"role": "user", "content": "Question about document"}
    ]
)

# Claude automatically caches the document
# Next 5 minutes: 90% discount on cached content

Cache duration: 5 minutes (ephemeral) or until end of conversation

📦 Strategy 4: Batch Processing
Batch API Benefits ›

Regular API: $30 per million input tokens

Batch API: $24 per million input tokens (20% discount)

When to use:

  • Processing 100+ items at once
  • Not time-sensitive (up to 24h wait ok)
  • Large scale operations

How it works:

Collect 1000 requests → Submit as batch → Wait for results

Get all results back in a few hours → Process them offline

Batch Processing Example ›

Bad approach (expensive):

Send each ticket individually, one by one. Cost: $30. Takes all day.

📊 Strategy 5: Monitoring & Budgets
Cost Tracking ›

Track every call:

import json
from datetime import datetime

def log_api_call(model, input_tokens, output_tokens, cost):
    log_entry = {
        "timestamp": datetime.now().isoformat(),
        "model": model,
        "input_tokens": input_tokens,
        "output_tokens": output_tokens,
        "cost": cost
    }
    
    # Append to log file
    with open('llm_usage.jsonl', 'a') as f:
        f.write(json.dumps(log_entry) + '\n')

# Use after every API call
response = client.messages.create(...)
input_tokens = response.usage.input_tokens
output_tokens = response.usage.output_tokens

# Calculate cost
model_rates = {
    "claude-3-5-sonnet": (0.003, 0.015),
    "claude-3-5-haiku": (0.0008, 0.004)
}

input_rate, output_rate = model_rates["claude-3-5-haiku"]
cost = (input_tokens * input_rate / 1000) + (output_tokens * output_rate / 1000)

log_api_call("claude-3-5-haiku", input_tokens, output_tokens, cost)

import json

# Read logs
costs_by_model = defaultdict(float)

    for line in f:

        token_counts[model] += entry['input_tokens'] + entry['output_tokens']

# Find inefficiencies
print("Cost breakdown:")
for model, cost in sorted(costs_by_model.items(), key=lambda x: x[1], reverse=True):
    tokens = token_counts[model]

# Recommendations

from anthropic import Anthropic
import json
from datetime import datetime
from collections import defaultdict

client = Anthropic()

# ==================== COST TRACKER ====================
class CostTracker:
    def __init__(self):
        self.logs = []
        self.costs_by_model = defaultdict(float)
        self.token_counts = defaultdict(int)
    
    def log_call(self, model, input_tokens, output_tokens):
        """Log API call and calculate cost"""
        rates = {
            "claude-3-5-haiku-20241022": (0.0008, 0.004),
            "claude-3-5-sonnet-20241022": (0.003, 0.015),
            "claude-3-opus-20250219": (0.015, 0.075)
        }
        
        input_rate, output_rate = rates.get(model, (0.003, 0.015))
        cost = (input_tokens * input_rate / 1000) + (output_tokens * output_rate / 1000)
        
        entry = {
            "timestamp": datetime.now().isoformat(),
            "model": model,
            "input_tokens": input_tokens,
            "output_tokens": output_tokens,
            "cost": cost
        }
        
        self.logs.append(entry)
        self.costs_by_model[model] += cost
        self.token_counts[model] += input_tokens + output_tokens
    
    def report(self):
        """Print cost report"""
        print("\\n" + "="*60)
        print("💰 COST REPORT")
        print("="*60)
        
        total_cost = 0
        for model, cost in sorted(self.costs_by_model.items(), key=lambda x: x[1], reverse=True):
            tokens = self.token_counts[model]
            print(f"{model}: ${cost:.4f} ({tokens:,} tokens)")
            total_cost += cost
        
        print(f"\\nTotal: ${total_cost:.4f}")
        print("="*60)

# ==================== OPTIMIZED CLASSIFIER ====================
class OptimizedClassifier:
    def __init__(self):
        self.tracker = CostTracker()
        self.cache = {}
    
    def count_tokens(self, messages, system=None):
        """Count tokens before sending"""
        response = client.messages.count_tokens(
            model="claude-3-5-haiku-20241022",
            system=system or "",
            messages=messages
        )
        return response.input_tokens
    
    def classify_simple(self, text, categories):
        """Classify using cheap model (Haiku)"""
        # Optimize prompt: concise, structured output
        prompt = f"""Classify this text into one category.
Categories: {', '.join(categories)}
Text: {text}
Output: CATEGORY"""
        
        # Count tokens first
        messages = [{"role": "user", "content": prompt}]
        token_count = self.count_tokens(messages)
        
        # Check if too many tokens
        if token_count > 10000:
            return None, "Too many tokens"
        
        # Use cheap model for simple classification
        response = client.messages.create(
            model="claude-3-5-haiku-20241022",
            max_tokens=50,  # Keep output short
            messages=messages
        )
        
        # Track cost
        self.tracker.log_call(
            "claude-3-5-haiku-20241022",
            response.usage.input_tokens,
            response.usage.output_tokens
        )
        
        result = response.content[0].text.strip()
        return result, "success"
    
    def classify_complex(self, text, categories, system_prompt):
        """Classify complex using Sonnet with caching"""
        messages = [{"role": "user", "content": f"Classify: {text}"}]
        
        # Use system with caching
        response = client.messages.create(
            model="claude-3-5-sonnet-20241022",
            max_tokens=100,
            system=[
                {
                    "type": "text",
                    "text": system_prompt,
                    "cache_control": {"type": "ephemeral"}
                }
            ],
            messages=messages
        )
        
        # Track cost (cached content is cheaper)
        self.tracker.log_call(
            "claude-3-5-sonnet-20241022",
            response.usage.input_tokens,
            response.usage.output_tokens
        )
        
        return response.content[0].text.strip(), "success"

# ==================== MAIN ====================
if __name__ == "__main__":
    print("🚀 Cost-Optimized Document Classifier\\n")
    
    classifier = OptimizedClassifier()
    
    # Categories
    categories = ["Technology", "Sports", "Business", "Health"]
    
    # Test documents
    documents = [
        "Apple released the new iPhone with AI features",
        "The championship game was won by a last-minute goal",
        "Stock market hits record high amid economic growth",
        "New study shows benefits of regular exercise",
    ]
    
    # Classify using cheap model first
    print("📊 Classifying with Haiku (cheap)...")
    for doc in documents:
        category, status = classifier.classify_simple(doc, categories)
        print(f"  '{doc[:40]}...' → {category}")
    
    # For complex task, use Sonnet with caching
    print("\\n📊 Classifying with Sonnet + Caching...")
    system_prompt = """You are an expert classifier.
Analyze text carefully and categorize it precisely.
Consider context and nuance."""
    
    complex_doc = "Recent advancements in quantum computing could revolutionize technology industry"
    
    # First call (not cached)
    result1, _ = classifier.classify_complex(complex_doc, categories, system_prompt)
    print(f"  Result: {result1}")
    
    # Second call (cached - 90% cheaper!)
    result2, _ = classifier.classify_complex(complex_doc, categories, system_prompt)
    print(f"  Result (cached): {result2}")
    
    # Show costs
    classifier.tracker.report()
    
    # Savings estimate
    print("\\n💡 OPTIMIZATION RESULTS:")
    print("  ✓ Used Haiku (5x cheaper than Sonnet)")
    print("  ✓ Used caching (90% cheaper on cached calls)")
    print("  ✓ Optimized prompts (fewer tokens)")
    print("  ✓ Tracked every call (know where money goes)")
    print("\\n  → Estimated savings: 70-85% vs naive implementation")

🔍 Deep Dive: Cost Analysis
Cost Breakdown Example ›

Scenario: Customer support chatbot, 10,000 conversations/month

Naive approach (no optimization):

  • Use Claude 3 Opus for everything
  • 1,000 input tokens per conversation
  • 200 output tokens per conversation
  • Cost: 10,000 × (1,000 × $15 + 200 × $75) / 1M = $150

With optimization:

  • Use Haiku for 70% (simple questions)
  • Use Sonnet for 30% (complex issues)
  • Add caching (system prompt cached)
  • Compress prompts (20% fewer tokens)
  • Cost: 7,000 × (800 × $0.8 + 200 × $4) / 1M + 3,000 × (800 × $3 + 200 × $15) / 1M = $4.48 + $8.64 = $13.12

Savings: 91% ($150 → $13.12)

Where Money Gets Wasted ›

1. Using most expensive model for everything (50% of waste)

Opus for classification? 75x more expensive than Haiku. Wasteful.

2. Redundant API calls (20% of waste)

Same document analyzed 100x without caching. Send it once, reuse.

3. Bloated prompts (15% of waste)

Unnecessary examples, flowery language, verbose instructions.

4. Full context when partial works (10% of waste)

Send 100KB document when 5KB relevant excerpt would work.

5. No monitoring (5% of waste)

Don't track costs → don't know what to optimize.

🎯 Deep Dive: Advanced Techniques
Semantic Caching ›

Regular caching: Exact match only

If user asks "What is AI?" vs "Tell me about artificial intelligence" → Different keys → No cache hit

Semantic caching: Match by meaning

Both similar questions → Same cached answer → Save 90%

How it works:

  1. Create embeddings of questions
  2. Find similar questions in cache
  3. If similarity > 90% → Reuse cached answer
  4. Otherwise → Call API and cache new answer

Tools: Zep, Momento, custom with embeddings

Response Caching ›

Idea: Cache model responses, not just inputs

Example: "What is quantum computing?" asked by 1000 users/day

  • API call 1: $0.03 (full cost)
  • API calls 2-1000: $0 (cached response)

Implementation:

cache = {}

def answer_question(question):
    # Check if we have cached answer
    if question in cache:
        return cache[question]
    
    # Call API
    response = client.messages.create(...)
    answer = response.content[0].text
    
    # Cache for 24 hours
    cache[question] = answer
    
    return answer
Sampling & Probabilistic Testing ›

Idea: Don't evaluate everything with expensive model

Example: Quality assurance

  • Generate 1000 responses with Haiku
  • Evaluate quality with Sonnet on 10% sample (100 items)
  • If quality ok → Deploy, done
  • If quality bad → Adjust and retry

Savings: 90% cheaper evaluation (test 10% not 100%)

Hierarchical Processing ›

Idea: Route to right model based on complexity

Process:

  1. Haiku analyzes: Is this simple or complex?
  2. If simple → Haiku handles it (done, cheap)
  3. If complex → Route to Sonnet
  4. Sonnet analyzes: Is this very complex?
  5. If very complex → Route to Opus

Most requests finish at Haiku → Massive savings
