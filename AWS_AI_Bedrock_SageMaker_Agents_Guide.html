🛏️ AWS Bedrock: Foundation Models Made Easy

What it is: AWS's managed service that gives you access to multiple foundation models (Claude, Llama, Mistral, Titan) without managing infrastructure.

Simple analogy: Like a hotel with multiple restaurants. You pick which model to use, AWS handles everything else.

Available Models:

Claude (Anthropic)

Most capable, great for reasoning and coding

Llama (Meta)

Open source, fast and efficient

Mistral

Good balance of speed and quality

Titan (AWS)

Custom AWS model, cheaper option

Bedrock Features:

  • 🔌 Easy API - Simple REST calls to any model
  • 📚 Knowledge Bases - RAG built-in
  • 🤖 Agents - Autonomous behavior with tools
  • 🎯 Guardrails - Content filtering and moderation
  • 📊 Model Evaluation - Test and compare models
  • 💰 On-Demand & Batch - Pay per token or batch processing
🤖 Agents for Bedrock: Autonomous AI

What it is: Bedrock's built-in service for creating autonomous agents that can make decisions and use tools.

Think of it as: An LLM + tool ecosystem all managed by AWS. No need for LangGraph - it's built-in.

What Agents Can Do:

  • Call AWS services (Lambda, DynamoDB, S3)
  • Call external APIs
  • Query databases
  • Perform calculations
  • Make decisions based on data
  • Loop until goal is achieved

🎯 Service Details & Use Cases
Bedrock in Detail ›

What you pay for: Input and output tokens (per million)

Models available:

  • Claude 3.5 Sonnet (Most capable)
  • Claude 3 Opus (Best reasoning)
  • Llama 3 (Fast, open source)
  • Mistral (Good balance)
  • Titan Text (AWS native)

Key feature: Knowledge Bases

Upload documents → Bedrock handles RAG automatically. Query your docs with any model.

Key feature: Guardrails

Filter harmful content. Define sensitive topics. Block certain outputs.

Agents for Bedrock in Detail ›

How it works:

  1. Define tools (what agent can do)
  2. Create agent (specify model and tools)
  3. Invoke agent (pass task)
  4. Agent autonomously uses tools until done

Tool types:

  • AWS service tools (Lambda, DynamoDB, S3)
  • API tools (Call any REST API)
  • Database tools (Query databases)
  • Custom tools (Your functions)

Pricing: Per invocation + tokens used

Agent handles looping automatically. You only pay for tokens used.

SageMaker in Detail ›

Use SageMaker if:

  • Training custom models on proprietary data
  • Need fine-tuning of foundation models
  • Building ML pipelines
  • Need A/B testing and model comparison
  • Have regulatory requirements

SageMaker Components:

  • Studio: Jupyter notebook environment
  • Training Jobs: Run on managed infrastructure
  • Processing Jobs: Data processing at scale
  • Endpoints: Deploy as REST API
  • Pipelines: Automate ML workflows

Pricing: Per compute hour + storage

More expensive than Bedrock but full control over training and deployment

🚀 Simple Project: Expense Analyzer Agent

Build an agent that analyzes business expenses, stores them in DynamoDB, and provides insights. Uses Bedrock for intelligence.

Project Goal

Create an AWS Agent that can store expenses, categorize them, and provide spending analysis. Use Bedrock for intelligence, Lambda for tools, DynamoDB for storage.

📋 Step-by-Step Implementation
1 Install AWS Libraries

Get the SDK:

pip install boto3 python-dotenv
2 Set Up AWS Credentials

Configure AWS CLI:

aws configure
# Enter: Access Key ID, Secret Key, Region (us-east-1)

Or set environment variables:

export AWS_ACCESS_KEY_ID="your-key"
export AWS_SECRET_ACCESS_KEY="your-secret"
export AWS_DEFAULT_REGION="us-east-1"
3 Build Agent System

Create expense_agent.py:

import boto3
import json
from datetime import datetime
import re

# ==================== AWS CLIENTS ====================
bedrock = boto3.client('bedrock-runtime', region_name='us-east-1')
dynamodb = boto3.resource('dynamodb', region_name='us-east-1')

# Table name
TABLE_NAME = 'expenses'

# Create table if needed (run once)
def create_table():
    """Create DynamoDB table for expenses"""
    try:
        table = dynamodb.create_table(
            TableName=TABLE_NAME,
            KeySchema=[
                {'AttributeName': 'expense_id', 'KeyType': 'HASH'}
            ],
            AttributeDefinitions=[
                {'AttributeName': 'expense_id', 'AttributeType': 'S'}
            ],
            BillingMode='PAY_PER_REQUEST'
        )
        table.wait_until_exists()
        print(f"✅ Table {TABLE_NAME} created")
    except Exception as e:
        print(f"⚠️ Table already exists or error: {e}")

# ==================== TOOLS ====================
class ExpenseTools:
    """Tools that the agent can use"""
    
    @staticmethod
    def add_expense(amount: float, category: str, description: str) -> dict:
        """Add expense to DynamoDB"""
        expense_id = f"exp_{datetime.now().timestamp()}"
        
        table = dynamodb.Table(TABLE_NAME)
        table.put_item(Item={
            'expense_id': expense_id,
            'amount': amount,
            'category': category,
            'description': description,
            'date': datetime.now().isoformat()
        })
        
        return {
            "success": True,
            "expense_id": expense_id,
            "message": f"Added ${amount} expense for {category}"
        }
    
    @staticmethod
    def get_expenses() -> dict:
        """Get all expenses from DynamoDB"""
        table = dynamodb.Table(TABLE_NAME)
        response = table.scan()
        items = response.get('Items', [])
        
        total = sum(item.get('amount', 0) for item in items)
        
        return {
            "success": True,
            "expenses": items,
            "count": len(items),
            "total": total
        }
    
    @staticmethod
    def analyze_expenses() -> dict:
        """Analyze spending by category"""
        table = dynamodb.Table(TABLE_NAME)
        response = table.scan()
        items = response.get('Items', [])
        
        # Group by category
        by_category = {}
        for item in items:
            cat = item.get('category', 'Other')
            amt = item.get('amount', 0)
            by_category[cat] = by_category.get(cat, 0) + amt
        
        return {
            "success": True,
            "by_category": by_category,
            "highest_category": max(by_category, key=by_category.get) if by_category else "None"
        }

# ==================== AGENT ====================
class ExpenseAgent:
    """Simple expense agent using Bedrock"""
    
    def __init__(self):
        self.tools = {
            "add_expense": ExpenseTools.add_expense,
            "get_expenses": ExpenseTools.get_expenses,
            "analyze_expenses": ExpenseTools.analyze_expenses
        }
        self.conversation = []
    
    def call_bedrock(self, prompt: str) -> str:
        """Call Claude via Bedrock"""
        self.conversation.append({
            "role": "user",
            "content": prompt
        })
        
        # Create system prompt that tells Claude about available tools
        system_prompt = """You are an expense manager agent. You help track and analyze expenses.

Available tools:
1. add_expense(amount, category, description) - Add a new expense
2. get_expenses() - See all expenses
3. analyze_expenses() - Get spending analysis by category

When user asks about expenses, use these tools to help them.
After using a tool, explain the results to the user.
Output format: First, show what tool you'll use. Then execute it.
Format: """
        
        response = bedrock.invoke_model(
            modelId='anthropic.claude-3-5-sonnet-20241022',
            contentType='application/json',
            accept='application/json',
            body=json.dumps({
                'system': system_prompt,
                'messages': self.conversation,
                'max_tokens': 1024
            })
        )
        
        result = json.loads(response['body'].read().decode())
        assistant_message = result['content'][0]['text']
        
        self.conversation.append({
            "role": "assistant",
            "content": assistant_message
        })
        
        return assistant_message
    
    def process_request(self, user_request: str) -> str:
        """Process user request and execute tools"""
        print(f"\\n👤 User: {user_request}")
        
        # Get Claude's response
        response = self.call_bedrock(user_request)
        print(f"\\n🤖 Agent: {response}")
        
        # Extract and execute tools
        self._execute_tools(response)
        
        return response
    
    def _execute_tools(self, response: str):
        """Parse response and execute tools if mentioned"""
        # Simple parsing for tool calls
        if "add_expense" in response.lower():
            # Extract numbers and text
            numbers = re.findall(r'\\d+(?:\\.\\d+)?', response)
            words = response.split()
            
            if numbers:
                amount = float(numbers[0])
                category = "general"
                description = "expense"
                
                # Try to guess category
                for word in words:
                    if word.lower() in ['food', 'lunch', 'dinner', 'breakfast']:
                        category = "food"
                    elif word.lower() in ['uber', 'taxi', 'flight']:
                        category = "transport"
                
                result = ExpenseTools.add_expense(amount, category, description)
                print(f"   ✅ Tool result: {result['message']}")
        
        elif "get_expenses" in response.lower() or "show expenses" in response.lower():
            result = ExpenseTools.get_expenses()
            print(f"   ✅ Found {result['count']} expenses, total: ${result['total']}")
        
        elif "analyze" in response.lower():
            result = ExpenseTools.analyze_expenses()
            print(f"   ✅ Top category: {result['highest_category']}")

# ==================== MAIN ====================
if __name__ == "__main__":
    print("💰 AWS Bedrock Expense Agent\\n")
    
    # Set up
    create_table()
    
    # Create agent
    agent = ExpenseAgent()
    
    # Test interactions
    requests = [
        "Add a $50 expense for lunch",
        "Add a $100 Uber ride",
        "Show me all my expenses",
        "What category am I spending the most on?"
    ]
    
    for request in requests:
        agent.process_request(request)
        print("-" * 60)
    
    print("\\n✨ Agent completed all tasks!")

🛏️ Bedrock Deep Dive
Model Selection Guide ›

Claude 3.5 Sonnet: Best overall. Fast, capable, good for most tasks.

Claude 3 Opus: Most capable. Best for complex reasoning and coding. Slower, more expensive.

Llama 3: Fast and open source. Good for simple tasks. Cheaper than Claude.

Mistral: Good balance. Fast enough for real-time, capable enough for complex tasks.

Titan Text: AWS native model. Custom trained. Good for specific AWS use cases.

Decision matrix:

  • Speed critical? → Llama 3 or Mistral
  • Quality critical? → Claude 3 Opus
  • Cost critical? → Llama 3
  • Balanced? → Claude 3.5 Sonnet (recommended)
Knowledge Bases (Bedrock RAG) ›

What it is: Built-in RAG system. Upload docs → Query with any model.

How to use:

  1. Create knowledge base in Bedrock console
  2. Upload documents (PDFs, docs, web pages)
  3. Index documents (automatic)
  4. Query using API

Supported formats:

PDFs, DOCx, TXT, web pages, markdown

Example query:

response = bedrock.retrieve_and_generate(
    input_text="What is our company policy?",
    retrieveAndGenerateConfiguration={
        'type': 'KNOWLEDGE_BASE',
        'knowledgeBaseConfiguration': {
            'knowledgeBaseId': 'your-kb-id'
        }
    }
)
Guardrails: Content Safety ›

What it is: Filter harmful content, block topics, define style guidelines.

Use cases:

  • Block violent, sexual, or hateful content
  • Prevent discussing sensitive company info
  • Enforce brand voice and tone
  • Compliance with regulations

How it works:

Create guardrail → Define rules → Apply to model calls

🤖 Agents Deep Dive
Agent Architecture ›
Agent Loop: 1. User provides task 2. Agent reads task 3. Agent decides: should I use a tool? 4. If yes: - Pick tool - Prepare input - Call tool - Get result - Go back to step 3 5. If no: - Return final answer to user

This loop is automatic. You just define tools and invoke the agent.

Defining Tools ›

Tool definition includes:

  • Tool name (what agent calls it)
  • Description (when to use)
  • Input schema (what parameters)
  • Handler function (what it does)

Example:

tool = {
    'name': 'get_weather',
    'description': 'Get current weather',
    'inputSchema': {
        'properties': {
            'location': {
                'type': 'string',
                'description': 'City name'
            }
        }
    },
    'handler': get_weather_function
}
Agent Best Practices ›

1. Clear tool descriptions: Agent needs to understand what each tool does

2. Single responsibility: Each tool should do one thing well

3. Error handling: Tell agent what went wrong if tool fails

4. Max iterations: Set limit to prevent infinite loops

5. Test tools independently: Before using with agent

🧠 SageMaker Deep Dive
When to Use SageMaker vs Bedrock ›

Use Bedrock if:

  • Using foundation models (Claude, Llama, etc.)
  • Quick integration needed
  • Don't want to manage infrastructure
  • Building chatbots, RAG, agents

Use SageMaker if:

  • Training custom models on your data
  • Fine-tuning foundation models
  • Need specialized models (computer vision, etc.)
  • Building ML pipelines
  • Have data science team
SageMaker Training Workflow ›
1. Prepare data (upload to S3) 2. Write training script (Python) 3. Create training job (specify instance type) 4. AWS runs training (manages infra) 5. Training outputs model (save to S3) 6. Deploy model (create endpoint) 7. Get REST API (call like any API) 8. Monitor and scale automatically

You focus on training logic, AWS handles infrastructure.

SageMaker Autopilot ›

What it is: Automated ML. Feed it data, get back best model.

How it works:

  1. Upload CSV with training data
  2. Select target column
  3. Autopilot tries many models
  4. Returns best one with results

Good for: Tabular data, classification, regression

Less control than custom training but much faster

💰 Pricing & Cost Optimization
Bedrock Pricing ›

Model Invocation: Per 1,000 input + output tokens

  • Claude 3.5 Sonnet: ~$0.003 input / $0.015 output
  • Llama 3: ~$0.00035 input / $0.00070 output

Knowledge Base: Per retrieval

Cost tips:

  • Use Llama for simple tasks
  • Cache prompts when possible
  • Batch processing cheaper than streaming
  • Monitor token usage
SageMaker Pricing ›

Training: Per compute instance hour (varies by type)

Hosting: Per compute instance hour for endpoint

Storage: Per GB in S3

Cost tips:

  • Use spot instances (70% cheaper)
  • Auto-scale endpoints
  • Stop unused endpoints
  • Use Graviton processors when possible
🏗️ Architecture Patterns
Pattern 1: Simple Chatbot ›
User → API Gateway → Lambda ↓ Bedrock (Claude) ↓ Response → User Best for: FAQs, customer support, general Q&A Complexity: Low Cost: Low per call
Pattern 2: RAG System ›
User Query → Bedrock Knowledge Base ↓ Retrieve docs → Claude reads docs ↓ Generate answer with sources Best for: Documentation, knowledge bases Complexity: Medium Cost: Per retrieval + per token
Pattern 3: Agent System ›
User → API → Bedrock Agent ↓ Think: What to do? ↓ Use Tool: Lambda / DynamoDB / S3 ↓ Observe Result ↓ Continue Loop or Return Answer Best for: Autonomous tasks, data queries Complexity: High Cost: Varies (loops use more tokens)
Pattern 4: Custom ML Pipeline ›
Data (S3) → SageMaker Training ↓ Custom Model ↓ Deploy to Endpoint ↓ REST API for inference Best for: Custom models, fine-tuning Complexity: High Cost: Training + hosting
🎓 Quick Decision Tree

Need to use LLMs?

  • Yes → Use Bedrock
  • No, training custom model? → Use SageMaker

Need autonomy?

  • Yes → Use Bedrock Agents
  • No, just responses → Just Bedrock

Need to access your data?

  • Yes → Add Knowledge Base + Lambda tools
